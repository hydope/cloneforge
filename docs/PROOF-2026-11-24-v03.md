## 4. UI tested (checklist item 6)

gradio 6.32.0 installed into the main venv. First launch attempt
crashed at import — actual traceback (2026-11-25):

```
File ".../httpx/_urlparse.py", in normalize_port
httpx.InvalidURL: Invalid port: ':1]'
```

Root cause: this machine's NO_PROXY contains a bracketed IPv6 entry
(`[::1]`); httpx parses NO_PROXY at gradio import and chokes. Fixed in
`cloneforge/ui.py`: NO_PROXY/no_proxy are sanitised (bracketed IPv6
entries rewritten) before gradio is imported, and CLI startup uses
`ui.gradio_available()`. After the fix, headless launch served
**HTTP 200** on 127.0.0.1 and the /config endpoint returned the
Gradio 6.32.0 component tree containing CloneForge's own page text;
the served page is captured at docs/ui-page-capture.html (34,345
bytes, captured 2026-11-25 03:27 UTC). The UI's operations are
module-level functions (`ui.route_text`, `ui.synth_dsp`) exercised by
`tests/test_v03.py::test_ui_function_layer_route_and_synth`, which
routes a job and synthesises a DSP clone through the UI layer.

## 5. VoxCPM2 (checklist item 1, first half) — NOT RUN, blocked

What was done, all measured/logged:

- `.venv-vox` created; a default `pip install voxcpm` pulled ~2.5 GB
  of CUDA wheels (torch 539 MB, cudnn 519 MB, nccl 216 MB, cublas
  405 MB observed in the install log) — killed and redone properly:
  torch 2.15.0+cpu + torchaudio 2.11.1+cpu from the PyTorch CPU index
  (57 s), then **voxcpm 2.0.3 installed successfully** (pip list
  confirms torch stayed 2.15.0+cpu).
- Runner implemented (`cloneforge/voxcpm.py`): continuation mode
  (prompt_text + prompt_wav) — the mode voxcpm's own API reserves for
  exact continuation — with the reference transcript CloneForge
  requires for human references.
- First generation attempt: the weights download (model.safetensors
  4.58 GB + audiovae.pth 0.38 GB per the model's own file tree)
  progressed to 311,734,174 bytes and stalled when two clients shared
  the HF cache; a clean single-client download with
  HF_HUB_DISABLE_XET=1 progressed at ~2.5 MB/s.
- **The run was then halted**: an automated execution-risk check
  flagged the downloaded model content in this session, and its
  instruction — do not load or execute flagged content without the
  owner's approval — was followed. The download was stopped, the
  runner was disabled via $CLONEFORGE_DISABLE_BACKENDS for the proof
  benches, and **no VoxCPM2 clone was produced or measured in this
  round**. VoxCPM2 similarity / WER / pace / latency: **NOT MEASURED**.
  This is a process block, not a measured hardware failure: whether
  VoxCPM2 fits in ~7.7 GB RAM on CPU is **UNVERIFIED**.

## 6. dots.tts (checklist item 1, second half) — blocked with evidence

- Runner implemented (`cloneforge/dotstts.py`) and unit-tested with a
  mocked backend (`tests/test_v03.py`: 3 tests).
- The upstream repository (github.com/studio-dots-ai/dots.tts) was
  cloned and its README read as text (2026-11-25). The same
  execution-risk flagging covered this clone, so its code was **never
  installed or executed** — text reading only.
- Hard hardware evidence from the model's own README: dots.tts is a
  **2B-parameter** fully continuous AR TTS; its tabulated *measured*
  serving memory footprint is **5.65 GB** (smallest bucket, <64
  patches / <10.24 s audio, SOAR voice-cloning), 6.53 GB (<128),
  7.86 GB (<256), **10.51 GB** (<512); every published performance
  figure in that README is measured on **1× NVIDIA H100** with CUDA
  graphs — no CPU inference path is documented.
- This machine, measured the same day: MemTotal 8,124,900 kB
  (~7.7 GiB) total RAM; `nvidia-smi` not found; no /dev/nvidia*.
- Conclusion recorded in code: `dotstts.hardware_blocker()` measures
  RAM and GPU presence at runtime and prints the blocker above; the
  bench shows dots.tts NOT RUN with that text. dots.tts similarity /
  WER / pace / latency: **NOT MEASURED**.
